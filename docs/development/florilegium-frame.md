# Florilegium continuous A4 garden

Implemented as `florilegium-continuous-v2` on 2026-11-06, using Florilegium revision `9fbaf56d53e6525e02da05cd802ea7da82052099` (release 2.0.1). The entry point is [page-engine.ts](../../src/engines/page-engine.ts). This replaces the experimental `florilegium-frame-v1` adapter, which assembled four rotated gardens and exposed visible composition seams.

## Source behavior and the continuous domain

Florilegium's supported [`florilegium-svg.page(options)`](../../florilegium/florilegium-svg.lua) initializes an actual Lua plant generator, colors and paper geometry. Its original composition fills the wider side margin and footer, optionally continuing beneath a text block. Its main stems assume that left-column composition. Calling the public interface on A4 alone therefore does not fill every side of an arbitrary reserved rectangle.

The [domain adapter](../../src/engines/page-domain.ts) makes one upstream page call, with one seed, one species community, one shared free-space field and one event schedule. All plants retain the native upright coordinate system. The free-space domain is the union of four overlapping rectangles around the reservation; they describe a single field, not four independently generated or clipped images. Its corners participate in the upstream distance calculation. A 1.8 mm geometric guard surrounds the reservation.

Three connected-region scaffold routes start in the original bottom-left root neighborhood. They rise along the left, pass through the bottom corridor and rise on the right, and reach the top through the left corridor. Their terminal tangents remain upright because upstream species heights and terminal flowers assume upward stems. Routes are sampled and rounded while checking complete segments against the exclusion. Density scales plant detail while all three structural routes remain available.

The original free-space selection, sampled species, plant drawing and branch generation remain upstream. Safe native branch curves pass through unchanged. A branch that would cross the reservation is rerouted using a deterministic visibility graph around its corners, while consuming the original branch's random draw once. Terminal flower scale is limited by available clearance. One exact page-minus-reservation clip surrounds the final scene as a safety boundary; there are no internal panel clips or rotations. Some legacy decorations or branches with an endpoint already inside the reservation still rely on that final clip. This is an experimental domain adaptation, not a claim that the upstream algorithm already supported arbitrary obstacles.

## Runtime adaptation

The application bundles Wasmoon 1.16.0 and its Lua 5.4 WASM runtime locally. A dedicated worker loads the pinned Lua files from the site's own `vendor/florilegium/` directory. Runtime URLs respect the GitHub Pages project subpath and make no CDN requests.

The submodule and distributed vendor files remain unchanged. [page-lua.ts](../../src/engines/page-lua.ts) applies checked hooks to the in-memory copy of `florilegium-grow.lua` before mounting it in Wasmoon. Each expected source anchor must occur exactly once; a different revision fails explicitly. The hooks provide scaffold replacement, stem count, terminal size limits, compact recording, stem centerlines and motif anchors. The adapter temporarily replaces exported `regions`, `branch_path`, `page` and visitor-drawing functions and restores them after success or error. The LPPL `florilegium-pgfmath.lua` file is not transformed.

## Continuous growth presentation

The engine API is `generate(settings, onProgress?, animate = false)`. It returns one static SVG. When `animate` is true, the result also contains `timeline: { svg, duration, events }`. The timeline SVG is byte-identical to the final SVG and includes an opaque paper background. It has a single A4 viewBox in PDF points and one y-up artwork group. Tagged drawing runs use `<g data-growth-event="e1">`; an event can have more than one run because upstream paint layers are preserved.

Events retain the upstream schedule in native seconds. Stem events include their centerline and width in PDF points; motif events include their anchor. The worker records only the final geometry for each event, skipping upstream's many earlier stem prefixes, scaled motif copies, visitor poses and explanatory overlays. It translates that final recording once. There are no full-page frame arrays, repeated full-page SVG image decodes or retained panel image URLs.

The browser measures that scene once, then rasterizes its paint-ordered event runs into tightly bounded canvas fragments with two concurrent decodes. Each fragment's temporary SVG URL and image are released after rasterization, and the measurement DOM is removed before playback. Canvas playback reveals stems along their native centerlines and scales motifs about their native anchors, using the original event starts, durations and parent relationships. A page-minus-reservation clip also applies during playback. The output SVG remains the original vector scene. Preview resolution targets 600–1200 pixels across the sheet and can decrease to keep the aggregate RGBA cache within approximately 24 million pixels; zoomed vector detail becomes available when playback finishes.

This preserves the order in which stems grow and their leaves and flowers open, with display updates between events. It is a compact presentation of native growth events, not a live view of each greedy placement iteration. Visitors appear at their final locations; upstream flying and crawling poses are not reproduced. The current browser player maps the native duration into 10–24 seconds and caches the compact vector scene for replay. Replay prepares the bounded raster fragments again. Cancellation aborts pending image decodes and releases all fragment canvases; preparation failure logs an explicit warning and reveals the completed vector garden.

Controls edit a draft. Only **Grow pattern** applies it; dragging or resizing the rectangle does not start generation. Replay uses the last completed scene. Cancellation terminates the busy worker and discards its result. A new request starts a fresh runtime when needed. Loading and execution errors are explicit, and a 120-second timeout terminates stalled work. The Lua stack is cleared and its garbage collector runs after each generation. Disabling growth playback yields the same final SVG without exposing a timeline to the interface.

## Settings, export and diagnostics

Version 1 settings contain a positive integer seed, rectangle coordinates in millimetres from the top-left corner of a 210 × 297 mm sheet, ink/accent/paper colors, density, season and allowed visitor groups. The rectangle is at least 40 × 40 mm and stays at least 18 mm from every edge. Density ranges from 0.2 to 1. SVG metadata includes the adapter version, upstream revision and complete settings; the SVG also has physical A4 dimensions and the selected paper color. Editor guides are not exported.

The original visitor interface is on/off. Our wrapper filters `florilegium-native.draw("visitor", ...)` by sampled genome group and restores the function afterward. This retains the upstream plant layout when visitor selections change, leaving reserved visitor space empty when disabled. An allowed visitor is still selected by the seed rather than guaranteed to appear. Butterflies include moths (`lepidoptera`); the engine also supports dragonflies/damselflies, beetles, caterpillars and flies for future controls.

Changing colors retains deterministic geometry. Reported motif totals are the upstream counts before the exact exclusion clip, and reported stems are upstream stem **sample points**, not individual stems. Visitor summaries describe allowed arrivals before clipping. Treat these values as generation diagnostics, not exact visible inventories. Reproducing an old v1 composition requires that old adapter revision; preserving its settings does not preserve its former four-garden output under v2.

## Verification and limits

The geometry tests exercise default, maximum-area, small and offset reservations. They verify scaffold containment, upright terminals, original root points, safe native branch passthrough, crossing-branch routing, one native RNG consumption and restoration of hooks. The Wasmoon integration tests execute the pinned Lua with the checked source hooks and verify reproducibility, finite event timing, scene/event consistency, static/timeline identity, A4 dimensions, paper color, selective visitors and invalid-setting rejection. Worker tests cover cancellation, stale results, timeout recovery and subpath-safe runtime URLs.

A local Node/Wasmoon smoke on 2026-11-06 generated the default geometry twice at density 0.55, including conversion and assertions, in 4.92 seconds for the full test process. The expanded 11-test engine/domain/worker suite passed in 7.51 seconds; it also compares every painted path from compact recording with a separate ordinary upstream static draw using the continuous domain. These are single-machine observations, not browser performance guarantees.

Initial browser experiments with direct SVG masks produced only 15–38 observed updates over roughly 20 seconds for an 8.75 MB dense scene, motivating the bounded Canvas presentation. Its first production-browser run rendered 714 Canvas frames over 17.3 seconds (about 41 frames/second) and showed continuous growth from the roots. This measurement preceded the aggregate 24-million-pixel cache guard; that guard and cancellation during preparation need the final browser regression check. Dense seeds, narrow margins and large botanical motifs can still produce crowded or clipped compositions. Browser interaction, playback, zoom, export and deployment require the application's separate smoke check; unit tests alone do not establish those behaviors.
